Core script logic
-----------------
1) Startup
   - script writes logger self-start event (source=logger, lifecycle=self, event=start)
   - optional history import runs once at start

2) Main loop
   - loop runs every --interval seconds
   - compares previous and current process snapshots
   - writes:
     - event=start when a process appears
     - event=end when a process disappears

3) Pause/resume controls
   - --pause creates control file cmd.paused
   - --resume removes cmd.paused
   - script writes logger pause/resume control events

4) Periodic help cooldown (Windows script)
   - default: every 3:33 minutes
   - script pauses for random 5-10 seconds
   - prints short help block
   - can be tuned by:
     --help-interval-sec
     --help-pause-min-sec
     --help-pause-max-sec
   - can be disabled by:
     --no-periodic-help

5) Shutdown
   - script writes logger self-end event with reason
   - pid file is cleaned up


Process data source and performance model
-----------------------------------------
The scripts use psutil process data.

Important optimization now used in both scripts:
- Instead of heavy process_iter(..., cmdline, ...) in each cycle,
  the loop reads only lightweight metadata:
  pid / name / create_time
  (see log_cmd.py and log_cmd_unix.py).
- cmdline() is called only for newly detected processes.
- Process identity is tracked by (pid, create_time), so PID reuse is handled safely.

Why this lowers CPU:
- cmdline collection for every process on every loop is expensive.
- metadata-only scans are much cheaper.
- full cmdline fetch is limited to new processes only.


Which processes can be logged
-----------------------------
- Usually: user-space processes visible to the current user/session.
- Sometimes limited:
  - protected/system processes can return AccessDenied
  - some short-lived processes can appear/disappear between scans
  - command line can be unavailable for restricted processes
- Such entries are skipped or partially logged by design.


Notes
-----
- For lower CPU, increase --interval (for example 4 or 5 seconds).
- Hard kill (for example taskkill /F or SIGKILL) may prevent clean self-end write.
